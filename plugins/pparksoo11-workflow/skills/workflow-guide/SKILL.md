# Workflow Orchestration Guide

pparksoo11의 Claude Code 작업 방식 가이드. 이 스킬을 통해 일관된 워크플로우 원칙을 어느 프로젝트에서나 참조할 수 있습니다.

## 1. Plan Mode Default

- **비자명한 작업(3단계 이상 또는 아키텍처 결정)에는 플랜 모드 진입**
- 뭔가 잘못되기 시작하면 즉시 STOP하고 재플랜 — 계속 밀어붙이지 않는다
- 플랜 모드는 구현뿐 아니라 검증 단계에도 사용
- 모호함을 줄이기 위해 상세 스펙을 선행 작성

## 2. Subagent Strategy

- 메인 컨텍스트 창을 깨끗하게 유지하기 위해 서브에이전트를 적극 활용
- 리서치, 탐색, 병렬 분석은 서브에이전트에 위임
- 복잡한 문제에는 서브에이전트를 통해 더 많은 컴퓨팅 투입
- 서브에이전트 1개당 1개의 집중된 작업

### 에이전트 팀 활용 예시
1. 리서치 & 리뷰: 다수 팀원이 문제의 다른 측면을 동시 조사
2. 새 모듈/기능: 각 팀원이 별도 파트를 독립적으로 소유
3. 경쟁 가설 디버깅: 다른 이론을 병렬로 테스트해 답에 빠르게 수렴
4. 크로스레이어 조율: 프론트/백엔드/테스트에 걸친 변경을 각 팀원이 담당

## 3. Self-Improvement Loop

- 사용자 교정 후에는 반드시 `tasks/lessons.md` 업데이트
- 같은 실수를 막는 규칙을 스스로에게 작성
- 실수율이 떨어질 때까지 무자비하게 반복
- 세션 시작 시 관련 프로젝트 레슨 리뷰

## 4. Verification Before Done

- 완료 증명 없이는 절대 작업을 완료로 표시하지 않는다
- 관련 시 main과 변경 사이의 동작 차이를 diff
- "스태프 엔지니어가 이 코드를 승인하겠는가?" 자문
- 테스트 실행, 로그 확인, 정확성 증명

## 5. Demand Elegance (Balanced)

- 비자명한 변경에는 잠깐 멈추고 "더 우아한 방법이 있는가?" 질문
- 해결책이 해키하다 느껴지면: "지금 아는 모든 것을 바탕으로 우아한 솔루션 구현"
- 단순하고 명확한 수정에는 적용 생략 — 과설계 금지
- 제출 전에 본인 작업에 스스로 도전

## 6. Autonomous Bug Fixing

- 버그 리포트가 주어지면: 그냥 고친다. 손잡아 달라고 하지 않는다
- 로그, 에러, 실패한 테스트를 가리킨 뒤 해결
- 사용자 컨텍스트 전환 불필요
- 방법을 알려주지 않아도 CI 실패 테스트를 스스로 수정

## Task Management

1. **Plan First**: 체크 가능한 항목으로 `tasks/todo.md`에 플랜 작성
2. **Verify Plan**: 구현 시작 전 체크인
3. **Track Progress**: 진행하면서 항목 완료 표시
4. **Explain Changes**: 각 단계에서 상위 수준 요약
5. **Document Results**: `tasks/todo.md`에 리뷰 섹션 추가
6. **Capture Lessons**: 교정 후 `tasks/lessons.md` 업데이트

---

## Core Principles

- **Simplicity First**: 모든 변경을 최대한 단순하게. 최소한의 코드만 영향 받게.
- **No Laziness**: 근본 원인을 찾는다. 임시방편 없음. 시니어 개발자 기준.
- **Minimal Impact**: 변경은 필요한 것만 건드려야 한다. 버그 도입 회피.

## Parallelism

병렬로 안전하게 실행 가능한 작업은 에이전트를 동시에 실행한다. 태스크에 따라 서브에이전트 또는 에이전트 팀을 선택한다.
