# Git Commit 스킬

변경 내용을 분석하여 간결하고 명확한 커밋 메시지를 자동 작성합니다.

## 규칙

- **제목**: 50자 이내, 동사 원형으로 시작 (Add, Fix, Update, Remove, Refactor 등)
- **본문**: 불릿(`-`) 형식으로 변경 내용 나열
- **저작권 표시 없음**: `Co-Authored-By` 등 AI 저작권 라인은 절대 추가하지 않음
- **언어**: 제목과 본문 모두 한국어로 작성 (단, 코드/파일명은 영어 유지)

## 커밋 메시지 형식

```
<타입>: <제목>

- <변경 내용 1>
- <변경 내용 2>
- <변경 내용 3>
```

### 타입 목록

| 타입 | 설명 |
|------|------|
| `feat` | 새 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 리팩토링 (기능 변경 없음) |
| `docs` | 문서 수정 |
| `style` | 코드 스타일/포맷 변경 |
| `test` | 테스트 추가/수정 |
| `chore` | 빌드, 설정, 의존성 변경 |
| `remove` | 파일/코드 삭제 |

## 워크플로우

### Step 1: 변경 내용 파악

```bash
git status
git diff --staged
git diff
```

스테이징된 변경이 없으면 모든 변경 파일을 스테이징합니다:

```bash
git add -A
```

단, `.env`, 시크릿 파일은 절대 포함하지 않습니다.

### Step 2: 커밋 메시지 작성

변경 내용을 분석하여:
1. 가장 적합한 타입 선택
2. 제목: 핵심 변경을 한 문장으로 요약
3. 본문: 구체적 변경 내용을 불릿으로 나열

### Step 3: 커밋 실행

```bash
git commit -m "$(cat <<'EOF'
<타입>: <제목>

- <변경 내용 1>
- <변경 내용 2>
EOF
)"
```

**반드시 지켜야 할 것:**
- `Co-Authored-By` 라인 추가 금지
- `🤖 Generated with` 라인 추가 금지
- AI 관련 저작권/출처 표시 일체 금지

### Step 4: 결과 확인

```bash
git log --oneline -1
```

커밋 완료 메시지와 커밋 해시를 사용자에게 보여줍니다.
